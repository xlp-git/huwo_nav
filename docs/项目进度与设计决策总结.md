# 虎窝导航 项目进度与设计决策总结

## 背景

"虎窝导航 / 小鹏导航"是个人网址导航站，技术栈为 React 19 + Vite 7，样式为手写 CSS（`src/App.css`），部署在 Cloudflare Pages，数据存 Cloudflare KV。本文根据 `CLAUDE.md` 的 Change Log 与 git 历史整理，截至 2026-09-24 Change Log #24。详细变更见 `CLAUDE.md` Change Log #1–#24。

## 内容

### 一、开发进度（已完成功能）

- **站点管理**：增删改查、批量删除（带确认，只作用于当前可见的已选站点）、全选；编辑模式下点整张卡片即选中，铅笔按钮编辑。
- **分类**：左侧竖排分类栏（桌面 200~260px 自适应、手机 92px 窄栏），内部滚动；新增分类后自动切换；编辑模式可重命名、删除分类（删除时可选站点移到未分类或连同删除）；没有分类的站点自动归入分类栏末尾的虚拟"未分类"；编辑模式下可拖动分类排序（手机长按拖动），顺序存 KV；“记录分类”开启时记住上次查看的分类（各设备通用），关闭时首页打开排第一的分类。
- **布局**：整页固定一屏高不滚动，分类栏和站点列表各自内部滚动；宽度铺满窗口，侧栏、时钟、留白随窗口大小自适应。
- **搜索**：限定当前分类；`/` 聚焦，回车打开第一个结果，无结果时用必应搜索，Esc 清空。
- **收藏夹导入**：浏览器端解析 Netscape HTML（嵌套文件夹、实体解码、过滤非 http 链接），按 URL 去重合并。
- **标题编辑**：浏览器标签页标题和首页标题，存 KV `app_settings`。
- **编辑模式**：密码由服务端校验（Cloudflare 环境变量 `EDIT_PASSWORD`），写接口统一鉴权。
- **外观**：起始页式布局——大时钟（含秒、日期、问候语）、居中搜索框；容器全透明，只有分类项、站点卡片等有文字的元素是毛玻璃，壁纸从间隙透出；Bing 壁纸边缘渐暗（静止，已去掉视差）；卡片描边随鼠标照亮、入场动画；横向长方形站点卡片（图标 + 名称/域名）。
- **交互细节**：通用弹窗（Esc/遮罩关闭、动画）、轻提示、统一确认框、加载骨架屏、卡片键盘可访问。

### 二、关键设计决策

1. **存储按环境区分**（`src/storage.js`）：生产环境读写走 `/api/*`，读取失败回退 localStorage 缓存（只读），**写入失败直接报错**，绝不静默写本地；本地开发（`vite dev`）全部走 localStorage。
   - 原因：旧版"API 失败就静默写本地"会让用户以为已保存，刷新后从 KV 读回旧数据，改动丢失。
2. **写接口服务端鉴权**：`functions/api/_middleware.js` 拦截 `/api/*` 非 GET 请求，校验请求头 `X-Edit-Password`（URI 编码，支持中文）与环境变量 `EDIT_PASSWORD`（SHA-256 摘要后逐字节比较）；未配置时拒绝写入（503）。
   - 原因：旧版密码以 `VITE_PASSWORD` 打包进前端 JS 可被直接读到，写接口也无鉴权。
   - 备选：保留前端密码校验（不安全，放弃）；未配置时放行写入（兼容但不安全，用户选择不采用）。
3. **收藏夹在浏览器端解析**：服务端只接收精简 JSON 并校验合并。
   - 原因：收藏夹文件常含大量 base64 图标，服务端解析会超出 Workers 免费版每次请求 10ms CPU 限额。
4. **分类不单独存储**：分类名从站点数组提取；空分类用 `isPlaceholder: true` 占位记录持久化，前端不展示占位记录。重命名/删除分类由 `/api/categories` 批量改写站点记录，一次写回 KV。分类显示顺序单独存在设置的 `categoryOrder` 中；设置接口按字段合并，避免不同功能的保存互相覆盖。
5. **数据集中在单个 KV 键**：`all_sites` 为完整 JSON 数组，另有 `app_settings`。每次写入都读出整个数组再写回，个人导航规模（几百站点）下无问题。
6. **记录分类存 KV、由唯一的免密写接口更新**：`app_settings.savedCategory` 按分类名记录（拖动排序不影响），开关开启时切换分类即通过 `PUT /api/last-category` 写入（值没变不写），刷新或换设备都恢复；关闭时清空记录，不写也不恢复，首页打开排第一的分类。
   - 原因：普通浏览不带密码也要能记录，所以单开一个只能改这一个字段的接口；最坏情况只是首页默认分类被改、消耗写入额度，不影响站点数据。
   - 演进：最初存 KV（写接口无鉴权）→ #17 加鉴权后改存本设备 localStorage（未迁移，旧记录丢失；且开关关闭时仍恢复旧记录，与 #23 拖动排序决定默认分类冲突）→ #24 按用户确认的语义改回 KV + 免密单字段接口。
7. **分类放左侧竖排栏 + 一屏固定布局**：分类一多不再把站点挤到下面；整页不滚动，分类栏与站点列表各自内部滚动，站点多了也不用拖动网页。
   - 演进：顶部单行横向滚动（分类多时像被裁掉）→ 顶部等宽网格换行（分类多时站点被挤下去）→ 左侧竖排栏 + 整页滚动（sticky 侧栏需 JS 算高度）→ 一屏固定布局、两栏各自内部滚动。
8. **全尺寸自适应**：不设内容最大宽度，留白、侧栏、时钟都用 `clamp()` 随窗口变化，站点网格自动增减列数；小屏和非最大化窗口也能完整显示。
9. **状态全部集中在 `App.jsx`**：不用 Context 或状态管理库；表单回调均为 async，失败抛错由弹窗内显示。
10. **图标单一来源 `favicon.im/zh/`**，失败显示地球 SVG；`faviconCache` 缓存结果，切换分类重新挂载时不再闪加载动画。
11. **毛玻璃只加在有文字的元素上**：容器全透明，每个分类项和站点卡片各自模糊背景，页面更通透。
   - 代价：滚动容器不能用 `mask-image` 做边缘渐隐（会让内部毛玻璃失效），滚动提示改靠细滚动条和半露的卡片。
   - 性能：同环境实测不比旧的整面板模糊慢。
12. **动效不触发 React 渲染**：卡片描边照亮只通过 rAF 写 CSS 变量；触屏和 `prefers-reduced-motion` 下关闭。壁纸视差已去掉（快速移动鼠标时整张壁纸平移，看起来像闪屏）。

### 三、遗留问题与注意事项

- **部署前必须配置 `EDIT_PASSWORD`**：Cloudflare Pages → 设置 → 环境变量（生产和预览都要），否则线上无法保存；旧 `VITE_PASSWORD` 可删除。
- **未在真实 Cloudflare 环境验证**：后端用模拟 KV + 直接调用 functions 代码测试（25 个用例通过），浏览器端用 Playwright 在开发模式和生产构建下验证。
- **超大收藏夹导入**：几千条书签时服务端合并与 KV 写回可能接近免费版 CPU 限额；几百条无问题。
- **登录无限速**：`/api/auth` 未做失败次数限制，依赖密码强度。
- **Tailwind 依赖未使用**：`src/index.css` 仍有 `@tailwind` 指令，可择机移除依赖。
